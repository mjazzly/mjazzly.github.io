The deepest one: the Meeting Tracker Assistant

A folder of meeting transcripts becomes a running list of who agreed to do what, by when, kept up to date week after week. The model does the reading and the judging; the rules sit in code it cannot skip.

The goal: every action agreed in a meeting is tracked with its owner and due date, and nothing is guessed. Where the transcript is unclear, it stops and asks.

Stops to askA name that matches two people in the contacts table. It will not pick one.
Stops to askA meeting with no actions. It will not invent one to fill the row.
Stops to askA due date before its own meeting. The record tool refuses the row.
DeclinesA transcript marked confidential is left unread and reported as declined.

How it runs: a small Node.js tool server on my machine, connected through MCP, holding the ten tools; the Claude desktop app starts it and calls the tools as it works. The tracker and the run log live in files on disk, so next week it reads only the new transcripts and never rewrites an old row. The contacts table stands in for a CRM; the data is synthetic.

Tested: five cases plus one it must decline, the expected results written before the first run, rerun blind on two model tiers.

How I know it works: the test harness

A test harness is a script that runs every test case the same way, checks the results against answers written first, and records them. It runs blind, meaning the model cannot see the expected answers, on any model tier, with the cost of every run recorded. That is how the smallest model that passes gets chosen.

The words on this page

  • Prompt. The instruction given to the model in a chat.
  • Claude Project. A workspace with standing instructions and files, so the same context is in place every time. ChatGPT's version is a custom GPT.
  • Skill. A packaged set of instructions Claude loads for a specific task. Some carry scripts.
  • Script. Code that does a step the same way every time, without the model deciding.
  • Tool. A function in code the model calls by itself to act. A prompt asks it to write; a tool lets it do.
  • Tool server. The program that holds the tools. Mine runs on my Mac; the Claude desktop app starts it.
  • API. The way code calls Claude directly, with a key, outside the chat app. The harness and the web app use it.
  • Node.js and Next.js. Node.js runs JavaScript outside the browser. Next.js is a website framework built on it: the pages and the server code in one project.
  • Test harness. A script that runs every test case the same way, checks the results against answers written first, and records them.
  • Blind run. A test where the model cannot see the expected answers.
  • Model tier. The size of model, from the largest to the smallest and cheapest.
  • Claude Code. Claude working inside a project folder: it writes the code, runs it and fixes it.
  • Spec and tickets. The written plan, broken into small pieces of work, each with a clear finish line.
  • Python, DuckDB, pytest. The language, a small database that lives in a file, and Python's testing tool.
  • Supabase, Stripe, Vercel. Accounts and data, payments, and hosting on the internet.
  • Prototype. A first working version, built to test the idea before the full build.
