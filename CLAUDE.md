# mjazzly.github.io, working rules for Claude Code

This is Megat Jazly's portfolio site (GitHub Pages, branch `main`, no build step: the HTML files are the site).
Positioning (re-led 1 Oct 2026): **data analyst as the door, AI workflows as the headline**. The eyebrow reads "Data Analyst · AI Workflows · Kuala Lumpur"; SQL appears only in the stack list, the certs and the hidden live blocks; never in the title, eyebrow, thesis, meta descriptions or any sentence that calls it a foundation, specialism or current focus (Megat is still learning SQL and has paused it to focus on AI). The word "enablement" stays off the site, and so do "agentic", "FDE" and "real users". The AI toolkit is Megat's own practice; never write it as team adoption at a client or employer. Every edit must keep all of this.

The Built page (added 27 Oct 2026) is the record of what Megat has built with Claude, at five depths. Every line on it is a fact from the record; a number on it changes only when the record changes. "Deployed" is said only of the Sustainability Self-Check web app and, since 31 Oct 2026, of WORK-03 data answers, whose public demo runs at https://data-answers.vercel.app on the smallest model with a daily cap, a per-visitor cap and its own spend limit; and, since 7 Nov 2026, of WORK-08, the meeting tracker run as a hosted service on a daily schedule (https://meeting-tracker-sable.vercel.app), live only from a green CI run and with a day of record. WORK-01 itself runs on his machine on synthetic data and is never called deployed; since 1 Nov 2026 it reads its transcripts from a Google Drive folder through the Drive API (the local folder remains for the blind harness), and the site says exactly that. "MCP" appears in one sentence only ("a small Node.js tool server on my machine, connected through MCP"); everywhere else say "connected tools". Client work on the page is described without the client.

## Hard rules
1. **Patch, never regenerate.** Edit the existing HTML in place with minimal diffs. Never rewrite a whole page.
2. **Reuse existing classes** (`.sys`, `.sys-head`, `.sys-id`, `.sys-status`, `.impact`, `.case`, `.case-top`, `.case-body`, `.beat`, `.beat-label`, `.slot`, `.principle`, `.stack-group`, `.certs`, `.badge`, `.badge-s`, `.ic`, and on the Built page `.stat`, `.stair`, `.deep`, `.gate`, `.tile`, `.strip`, `.words`, `.panel`, `.figure`). Amber is for verdicts and marks only: the ticks (the In use pill and the certifications), the Principle and In practice labels, the Role and Shape labels (plain text, never pills), stop points, and the gold seam beside the brand name. The two seams around the name, marine before it and amber after it, are his own mark (silver and gold) and stay on every page. They come together on hover (pointer devices only, so a tap never leaves them stuck) and, on the Systems page only, arrive joined, hold for about half a second so the join is seen, then part over 0.7s; the hero map starts as the parting ends. The paper is a neutral grey (#F3F4F6, never green), the header bar is white with a line under it. Headings are sentence case, never capitals or title case. No inline styles. New CSS only in `motion.css`, and only when the user asks for a visual change. Motion rule: nothing moves on its own; a drawing plays once when the reader scrolls to it or rests the pointer on its card, the staircase rises once, and reduced motion shows everything complete. No fade-ups on sections and no hover lift on plain cards.
3. **No em dashes or en dashes anywhere.** Use commas, colons, or "to" for ranges. Hyphens inside compound words are fine.
4. **The word "marketing" never appears on the site**, in any form. Use "commercial", "paid channels", "CRM", "account-based".
5. **Status pills are truthful and in plain words.** A running system shows "In use" with an amber tick, in the marine tint (amber and "In production" read as unfinished to a general reader, so neither is used). For other states: In progress, Queued, Shipped (sentence case on the visible pages since 27 Oct 2026; the hidden LIVE blocks and `scripts/ship.py` still carry the older capitals and are made sentence case the day a block is shipped). Never write Shipped by hand; only `scripts/ship.py` does that, and only when the artefact is live. ## Commit and push
- When `style.css`, `motion.css` or `site.js` changes, bump the `?v=` date on their links in every page (e.g. `?v=20261027` to `?v=20261103`), so visitors' browsers fetch the new file instead of a cached one.
- Commit messages: imperative, one line, what changed and where. Example: `Ship Project A: unhide LIVE-A on index and casefiles`.
- Push to `origin main`. GitHub Pages redeploys in about a minute; the live URL is https://mjazzly.github.io.
- Never force-push. Never rewrite history. If `git pull` conflicts, stop and show the user the conflict.

## Shipping a project
- `python3 scripts/ship.py A` (or `B`), optionally `--label "SHIPPED · OCT 2026" --questions 20`.
- Then add the public link inside the shipped card if the user gives one (Power BI publish-to-web URL for B).
- Then `scripts/check.py`, then commit and push.
