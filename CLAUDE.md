# mjazzly.github.io, working rules for Claude Code

This is Megat Jazly's portfolio site (GitHub Pages, branch `main`, no build step: the HTML files are the site).
Positioning (re-led 1 Oct 2026): **data analyst as the door, AI workflows as the headline**. The eyebrow reads "Data Analyst · AI Workflows · Kuala Lumpur"; SQL appears only in the stack list, the certs and the hidden live blocks; never in the title, eyebrow, thesis, meta descriptions or any sentence that calls it a foundation, specialism or current focus (Megat is still learning SQL and has paused it to focus on AI). The word "enablement" stays off the site, and so do "agentic", "FDE" and "real users". The AI toolkit is Megat's own practice; never write it as team adoption at a client or employer. Every edit must keep all of this.

The Built page (added 27 Oct 2026) is the record of what Megat has built with Claude, at five depths. Every line on it is a fact from the record; a number on it changes only when the record changes. "Deployed" is said only of the Sustainability Self-Check web app; the meeting tracker runs on his machine on synthetic data and is never called deployed. "MCP" appears in one sentence only ("a small Node.js tool server on my machine, connected through MCP"); everywhere else say "connected tools". Client work on the page is described without the client.

Do not edit it unless the user asks explicitly.

- `scripts/icons.py` the icon set: 40 line pictograms drawn as SVG symbols and written into every page as an inline sprite between `<!--ICONS-->` markers; a page uses one with `<svg class="ic" aria-hidden="true"><use href="#ic-name"/></svg>`. Add an icon there, rerun the script, never paste icon paths into a page.
- `favicon.svg`, `favicon-32.png`, `apple-touch-icon.png` the site icon (an M on a marine square with an amber base); regenerate the PNGs from the SVG with `scripts/favicon.py`.
- `site.js` plays a drawing the first time it scrolls into view, replays it once when the pointer rests on its card (never on a timer, never restarting mid-play) (the other Models cards step back), lights one step of a swimlane when the pointer rests on its column (the rest dim, the drawing sits complete), and reveals the staircase. Without it nothing is hidden.
- `scripts/diagrams.py` draws every swimlane diagram (casefiles.html CASE-01 to CASE-03, built.html tracker and harness) from the specs inside it, between `<!--DIAGRAM:name-->` markers: a solid line closes the lane-label column, every part carries `data-step`, and an invisible column per step takes the pointer. Edit the spec, run it, never hand-edit the SVG. An arrow never passes behind a box (the generator routes down or up first when a straight run would cross one), box labels are set in Manrope with code names in Plex Mono, and every label keeps at least 4px clear of every box edge, top and bottom included: keep labels to two short lines, plus the amber stop note if the box has one (lanes are 72px tall to fit three lines).
- `scripts/shot.py` renders every page to PNG (desktop and phone) for review before a commit.
- The footer is identical on every page: one panel, "Hiring, or just curious? Get in touch." and three icon links (an envelope drawn inline; the LinkedIn and GitHub marks from Bootstrap Icons 1.11.3 on cdn.jsdelivr.net, painted in the link colour through a CSS mask; Simple Icons no longer carries LinkedIn). Never add page-specific footer copy; the main event is the top of the page.
- `scripts/check.py` pre-publish checks (run before every commit)
- `scripts/ship.py` flips a hidden live-project block to SHIPPED

## Hard rules
1. **Patch, never regenerate.** Edit the existing HTML in place with minimal diffs. Never rewrite a whole page.
2. **Reuse existing classes** (`.sys`, `.sys-head`, `.sys-id`, `.sys-status`, `.impact`, `.case`, `.case-top`, `.case-body`, `.beat`, `.beat-label`, `.slot`, `.principle`, `.stack-group`, `.certs`, `.badge`, `.badge-s`, `.ic`, and on the Built page `.stat`, `.stair`, `.deep`, `.gate`, `.tile`, `.strip`, `.words`, `.panel`, `.figure`). A new card or section heading gets a `.badge` with an icon from `scripts/icons.py`, and a section heading never repeats an icon used on a card in that section. Amber is for verdicts and marks only: the status pill, the Principle and In practice labels, the Role and Shape labels (plain text, never pills), stop points, and the gold seam beside the brand name. The two seams after the name, marine then amber, are his own mark (silver and gold) and stay on every page. The paper is a neutral grey (#F3F4F6, never green), the header bar is white with a line under it. Headings are sentence case, never capitals or title case. No inline styles. New CSS only in `motion.css`, and only when the user asks for a visual change. Motion rule: nothing moves on its own; a drawing plays once when the reader scrolls to it or rests the pointer on its card, the staircase rises once, and reduced motion shows everything complete. No fade-ups on sections and no hover lift on plain cards.
3. **No em dashes or en dashes anywhere.** Use commas, colons, or "to" for ranges. Hyphens inside compound words are fine.
4. **The word "marketing" never appears on the site**, in any form. Use "commercial", "paid channels", "CRM", "account-based".
5. **Status pills are truthful.** In production, In progress, Queued, Shipped (sentence case on the visible pages since 27 Oct 2026; the hidden LIVE blocks and `scripts/ship.py` still carry the older capitals and are made sentence case the day a block is shipped). Never write Shipped by hand; only `scripts/ship.py` does that, and only when the artefact is live. Identifiers read "SYS-04 / Data quality pipeline" and "CASE-02 · Data expansion pipeline": the code in capitals, the name in sentence case.
6. **Hidden live blocks** sit inside `<!--LIVE:... LIVE:END-->` comments. Leave them hidden until the user says the project is done. Never put `--` inside those comments.
7. **Nav order** on every page: Built, Case Files, Systems, Operator, Models.
8. **Case Files keep the arc:** Context, Problem, Approach, System, Result (or Status), Principle, with a swimlane drawing above the arc (steps across, who or what does each step down, stop points in amber). Each case is folded: the title and the drawing show, and a "Read the case" button opens the arc (`.case-foot` with `.case-toggle`, the body carries an id `case-NN-body`). Without JavaScript every case stays open. No client stakeholder names ever; client company names are fine.
9. **Numbers are the record's, and the CV follows**: 90%, 20+, 9 to 10; the Systems page says 2,700+ validated records (the engagement's data expansion, 2,766 at 23 Oct 2026) and CASE-02 says 21,000+ (expansion plus the list enrichment, 21,086). The CV still says 2,300+ and is updated to 2,700+ the next time it is revised; if a site number changes, tell the user whether the CV must change too.
10. Run `python3 scripts/check.py` before every commit. Fix failures, do not bypass them. After any diagram spec change, run `python3 scripts/diagrams.py` first; after any visual change, `python3 scripts/shot.py <folder>` and look at the renders.

## Commit and push
- When `style.css`, `motion.css` or `site.js` changes, bump the `?v=` date on their links in all five pages (e.g. `?v=20261027` to `?v=20261103`), so visitors' browsers fetch the new file instead of a cached one.
- Commit messages: imperative, one line, what changed and where. Example: `Ship Project A: unhide LIVE-A on index and casefiles`.
- Push to `origin main`. GitHub Pages redeploys in about a minute; the live URL is https://mjazzly.github.io.
- Never force-push. Never rewrite history. If `git pull` conflicts, stop and show the user the conflict.

## Shipping a project
- `python3 scripts/ship.py A` (or `B`), optionally `--label "SHIPPED · OCT 2026" --questions 20`.
- Then add the public link inside the shipped card if the user gives one (Power BI publish-to-web URL for B).
- Then `scripts/check.py`, then commit and push.
