The report that ate Mondays

CASE-01 · REPORTING PIPELINE
Context

A weekly performance report for a US-based client pulled 20+ metrics from five advertising and CRM platforms (Google, Bing, LinkedIn, Meta, Salesforce). The audience was the client's marketing leadership, who needed it reliably every week to steer spend.

Problem

Every Monday, hours went into exporting, reconciling, and reformatting the same numbers by hand. The report was accurate, but the person producing it was the pipeline, and that is a single point of failure, not a process.

Approach

The constraint shaped everything: no data warehouse, no engineering support, no budget for tooling. So the rule was build inside the tools already on the desk, and make it inspectable, not magical. Separate the work into ingest, clean, and consolidate, then encode the cleaning rules that until then lived only in one head.

System

A Power Query pipeline that ingests each platform export, standardises naming and formats, applies the documented cleaning rules, and lands everything in a single source of truth table feeding the client dashboard. Every transformation step is written down, so a colleague can inspect and run it.

Result

Weekly manual preparation time down over 90%. Reconciliation errors near zero because the rules run identically every week. Monday mornings returned to analysis instead of assembly, and the process survived a full handover test: someone else ran it without me in the room.

Principle

Automation on top of an unexamined process just makes mistakes faster. Map and fix the workflow first, then automate the version that works.

Teaching AI to be checkable

CASE-02 · GENAI DELIVERY WORKFLOWS
Context

Across several US client accounts, Generative AI was becoming part of everyday delivery: list building, data cleaning, and persona classification run through Claude, ChatGPT, and Gemini. The audience was internal delivery teams under deadline, and the appeal was obvious, the work went faster.

Problem

Faster is worthless if it is wrong. Prompts were improvised per person and per task, so results varied by who ran them, and there was no checkpoint between an AI-generated output and a client deliverable. The risk was quiet: a plausible-looking but incorrect result slipping through unnoticed.

Approach

I framed it as two separate problems, not one. Consistency is an input problem: fix it by standardising the prompts. Correctness is an output problem: fix it with a checkpoint before deployment. Treating them separately meant each could be solved properly instead of hoping a single clever prompt did both.

System

Two connected pieces. First, structured prompt testing: each use case gets prompts designed, tested against real cases, and refined into a reusable library, so the same task runs the same way regardless of who runs it. Second, an output validation protocol: verified checkpoints an output must pass before it enters a client deliverable, backed by a versioned playbook documenting the rules.

Result

Turnaround time and consistency of deliverables improved by 90%, while the validation layer kept inaccurate outputs out of client work and cut rework. AI shifted from a personal shortcut to a governed, repeatable part of delivery that a new team member could adopt safely.

Principle

Speed from AI is only an asset once it is checkable. Standardise the input for consistency, validate the output for trust, and never let one depend on the other.
