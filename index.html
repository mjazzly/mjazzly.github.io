Operating principles

Foundations first, then automate

Automation built on an unexamined process just makes mistakes faster. I map the workflow, fix the data quality, then build the system.

Validate before deployment

Every number and every AI-assisted output passes verified checkpoints before it reaches a stakeholder. Speed is only useful when the answer is right.

Document so it survives handover

A system that lives in one person's head is a liability. Everything I build ships with versioned guides a colleague can run without me.

Systems I run

SYS-01 / Validation protocol and data playbookIn use

Output validation and the versioned data playbook

The protocol makes two checks: that a workflow agrees with a verified answer key before it goes live, and that every output meets the written checkpoint rules before it enters a deliverable. I sign off at both checkpoints. The rules, metric definitions and delivery decisions live in one versioned playbook a colleague can run from.

See the protocoldrawn step by step in CASE-01

SYS-02 / GenAI delivery workflowsIn use

Three recurring outputs, one structure every run

Three outputs recur: meeting notes turned into summaries and action lists, decks built to one template, and a weekly data expansion cycle. Each keeps the same structure every run, tested on a five-case rehearsal across Claude, ChatGPT and Gemini, and a person reviews every output before it leaves.

SYS-03 / Packaged AI assistantsIn use

Modular assistants with executable documentation

Recurring workflows packaged as assistants (a guide, reference documents and scripts), so the same process runs the same way whoever runs it. The public builds carry their record: 34 tools across four tool servers, and 7 assistants tested against answers written first.

SYS-04 / Data quality pipelineIn use

Validated data expansion for a CRM

A staged pipeline for growing a contact database: the source export, scope and duplicates, email validation in a separate tool, results merged, then a CRM-ready file with a status on every record. Every round runs the same steps and checks, with a stop for the count at each stage, and every record is logged in a quality ledger.

SYS-05 / Reporting pipelineIn use

Multi-source reporting pipeline, single source of truth

Exports from several platforms (CRM and paid channels) are consolidated by one refreshable query into one report: every file read, names and formats standardised, the written cleaning rules applied, and the row counts reconciled before the report refreshes. Every transformation rule is documented and inspectable.
